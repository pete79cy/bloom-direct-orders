# Προσφορές μέσα στο Direct Orders — Design

**Date:** 2026-09-27
**Repos:** bloom-direct-orders (PWA) + bloom-crm (δύο μικρές αλλαγές API)
**Status:** Υλοποιήθηκε στο branch `claude/mobile-offers-bloom-app-mwk960` και των δύο repos

## Απόφαση

Οι προσφορές μπαίνουν ως **δεύτερη λειτουργία στο ίδιο PWA**, όχι ως ξεχωριστό
app. Η αρχική οθόνη μοιράζεται σε δύο κάρτες, **Νέα Προσφορά** πάνω και **Νέα
Παραγγελία** κάτω. Το bottom nav αποκτά tab «Προσφορές».

Μια πρώτη εκδοχή του spec πρότεινε ξεχωριστό app `bloom-offers` με δικά του
endpoints (`POST /api/direct-quotes`, `PATCH /api/quotes/:id`). Απορρίφθηκε:
ο χρήστης θέλει «να ακολουθεί όλα τα functionality του Bloom», και η
αποθήκευση προσφοράς στο Bloom κάνει πολλά που ένα παράλληλο endpoint θα
έπρεπε να ξαναγράψει.

## Αρχή: ένα μονοπάτι εγγραφής, αυτό του Bloom

Κάθε εγγραφή προσφοράς από το PWA (δημιουργία, αποστολή, αποδοχή, απόρριψη,
σημειώσεις, παράταση ισχύος) πηγαίνει στο **`POST /api/quotes/save`**, το ίδιο
endpoint που χρησιμοποιεί ο desktop QuoteBuilder. Έτσι τρέχουν αυτούσια:

| Κανόνας Bloom | Πότε |
|---|---|
| Αρίθμηση QT-YYYY-NNN (advisory lock) | δημιουργία |
| `quote_status_history` με τον χρήστη του JWT | κάθε αλλαγή status |
| 422 `UNPRICED_LINES` | έξοδος από DRAFT |
| 422 `GROUP_PRICE_DEVIATIONS` + `price_scope` ανά γραμμή | DRAFT → SENT σε πελάτη ομίλου |
| Εγγραφή τιμοκαταλόγου πελάτη / ομίλου (`routePersonalWrite`) | κάθε αποθήκευση |
| Πάγωμα spec γραμμής (γλάστρα, ύψος) | αποστολή |
| Σφράγισμα κόστους ιδίας παραγωγής (`stampOwnCosts`) | έξοδος από DRAFT |
| Auto-match γραμμών από learned aliases | κάθε αποθήκευση |
| Κλείδωμα ACCEPTED / CONVERTED, κλείδωμα παλιάς αναθεώρησης | κάθε αποθήκευση |
| Αυτόματη παραγγελία (`syncAcceptedQuoteToOrder`) | SENT → ACCEPTED |

Η αποστολή μέσω Gmail χρησιμοποιεί το υπάρχον `POST /api/quotes/:id/send-gmail`
(δημιουργεί πρόχειρο στο Gmail), αφού πρώτα η προσφορά περάσει σε SENT μέσω save.

## Αλλαγές στο bloom-crm

1. **`POST /api/quotes/save`**: μια *νέα* προσφορά μπορεί να παραλείψει το
   `quote_number`. Ο αριθμός κόβεται μέσα στο transaction από την κλειδωμένη
   ακολουθία. Η απάντηση επιστρέφει `quoteId` και `quoteNumber`.
2. **`POST /api/quotes/save`**: το σφράγισμα κόστους τρέχει και για νέα
   προσφορά που αποθηκεύεται απευθείας ως SENT (πριν σφραγιζόταν μόνο
   υπάρχουσα DRAFT → SENT).
3. **`GET /api/quotes/:id`** (νέο): header, γραμμές `quote_lines` αυτούσιες για
   round-trip, μπλοκ `display` ανά γραμμή, πελάτης με τηλέφωνο/email πρώτης
   επαφής, ιστορικό, συνδεδεμένη παραγγελία, `isLatestRevision`. Οι
   ημερομηνίες επιστρέφονται ως `YYYY-MM-DD`, γιατί ο server τρέχει σε UTC+3
   και το JSON ενός `date` θα έδειχνε την προηγούμενη μέρα. Χωρίς αυτό κάθε
   αλλαγή status θα μετακινούσε την ισχύ μία μέρα πίσω.

## PWA

| Route | Σελίδα |
|---|---|
| `/` | Δύο κάρτες (Προσφορά πάνω, Παραγγελία κάτω) με μετρητές, πρόσφατα μικτά |
| `/quotes` | Λίστα με φίλτρα Ανοιχτές / Πρόχειρες / Εστάλησαν / Έληξαν / Αποδεκτές / Απορρίφθηκαν / Όλες |
| `/quotes/new` | Ο ίδιος wizard με τις παραγγελίες σε `mode="quote"` |
| `/quotes/:id` | Λεπτομέρειες, timeline, ενέργειες ανά status |

**Wizard:** Πελάτης και Γραμμές είναι κοινά. Το βήμα Στοιχεία έχει έκδοση,
ισχύ (chips 15/30/60, default 30), όρους (θυμάται τους τελευταίους) και
σημειώσεις. Ο Έλεγχος έχει δύο κουμπιά, Πρόχειρο και Αποστολή. Γραμμή εκτός
καταλόγου μένει *χωρίς αντιστοίχιση* (`offered_variant_id = null`), που είναι
το «needs matching» του Bloom. Δεν δημιουργεί πρόχειρο φυτό όπως οι παραγγελίες.

**Λεπτομέρειες, ενέργειες ανά status:**

| Status | Κύριο κουμπί | Άλλα |
|---|---|---|
| DRAFT | Αποστολή | PDF, Παράταση, Απόρριψη, Αντίγραφο |
| SENT | Αποδοχή πελάτη | PDF, Ξαναστείλε, Παράταση, Απόρριψη, Αντίγραφο |
| ACCEPTED με παραγγελία | Άνοιγμα ORD-… | PDF, Αντίγραφο |
| REJECTED / παλιά αναθεώρηση | Αντίγραφο ως νέα | PDF |

«Έληξε» εμφανίζεται όταν `valid_until` έχει περάσει, χωρίς να αλλάζει το
status στο Bloom (το Bloom δεν έχει job που να το κάνει).

**Αποστολή:** πρώτα save σε SENT, μετά PDF. Κοινοποίηση μέσω share sheet
(Viber, WhatsApp, Mail με συνημμένο), πρόχειρο Gmail μέσω Bloom, ή λήψη.
Επιλογή γλώσσας ΕΛ/EN, με προεπιλογή τη γλώσσα του πελάτη.

**PDF:** το πρωτότυπο PDF του Bloom. Το bloom-crm τρέχει τον ίδιο generator με
το desktop (`src/lib/pdf-utils.ts → generateQuotePDF`) στον server, στο
`GET /api/quotes/:id/pdf`, και το app απλώς το κατεβάζει. Όπως στο desktop,
δεν βγαίνει PDF όσο κάποια γραμμή είναι χωρίς αντιστοίχιση. Γι' αυτό μια
προσφορά με γραμμές εκτός καταλόγου αποθηκεύεται ως πρόχειρο και ολοκληρώνεται
στο Bloom.

## Εκτός scope (μένουν στο desktop)

Αναθεωρήσεις, εναλλακτικές γραμμές (επιστρέφονται αυτούσιες στο save αλλά δεν
εμφανίζονται), sourcing προμηθευτών, audit γραμμών, αντιστοίχιση γραμμών χωρίς
φυτό, επεξεργασία γραμμών υπάρχουσας προσφοράς.
